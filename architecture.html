一套模型契约，连接开发与运行

开发平台维护模型、界面与代码扩展，测试环境验证应用，目标环境中的统一运行时基座负责实际运行。从整体协作到模型装配，了解各部分如何连接、由谁执行。

01

企业级应用基座，一图看清能力全貌

AI 辅助开发、IDE 专业开发与可视化构建沉淀为应用资产，由统一应用基座承载。身份与访问控制、插件机制贯穿前后端，云原生支持与技术生态提供运行支撑。

02

开发、验证与部署，职责各自清楚

开发平台本身也复用统一运行时基座。交付后的应用由目标环境独立加载运行，后续开发继续在开发平台完成。

开发平台

在线编辑模型与界面资源，管理应用工作区和版本，创建开发助手与测试运行环境。

开发助手与测试环境

开发助手发现代码扩展中的元数据；测试环境加载当前应用，回传运行日志与状态，供开发者联调验证。

应用部署环境

目标基座装配已交付的模型与扩展，使用独立的配置、访问入口和业务数据处理请求。

03

开发平台：围绕应用工作区组织开发

建模界面、模型开发服务、应用管理和运行管理协作，保存业务定义、扩展依赖、界面资源及版本内容。

模型设计与校验

业务模型、页面、逻辑流与审批流使用各自的编辑器和模型契约；动作、事件与订阅可查看定义来源和实现绑定。

应用与资源管理

应用、版本、后端扩展包、模块树、内置角色和岗位随应用组织；数据源与平台组件库等资源供应用按需引用。

运行与联调

通过 Docker 或 Kubernetes 调试后端管理开发助手与测试实例，启停资源并查看日志和运行状态。

04

统一运行时基座：前端呈现，后端执行

前后端基座围绕同一套应用定义协作，通过 HTTP 和 WebSocket 连接。公共运行机制供开发平台和业务应用共同复用。

前端基座

组织菜单、路由、页签与弹窗；用 PrismUI 渲染 UI Schema，承载微前端与组件包，并提供认证、请求、主题和国际化接口。

后端基座

装配模型与扩展，运行数据访问、业务动作、逻辑流和审批流，提供通知、任务调度、RPC 和文件等公共能力。

技术与接入

前端以 React 和 SDK 组织扩展，后端以 Java 21、Spring Boot 和 SPI 装配模块；数据库、缓存、消息队列与外部服务通过适配器连接。

05

从元数据定义，到真正生效的运行模型

程序与插件、应用目录和支持的运行时来源提供定义。各类模型按自己的规则解析、合并或覆盖，再进入构建与注册过程。

业务语义投影

业务模型投射数据、页面、接口和权限等定义；投射结果继续进入目标模型的正式装配流程，目标模型保留自己的契约。

分层定制

产品基础与应用差异分别保存。模块树可合并菜单与权限引用，UI Schema 则选择高优先级的完整定义，具体取舍由模型类型决定。

生效与刷新

模型构建后注册页面路由、接口和执行契约。变更按对应模型的刷新或重启要求生效，应用资源与模型运行时各司其职。

06

一次业务请求，如何走到数据与执行引擎

UI 模型决定页面入口，UI Schema 描述内容与交互。WebAPI 按契约分派业务请求，逻辑流或代码实现具体处理，再通过数据模型访问数据。

动作执行

业务动作声明输入、输出和权限，由统一运行时进行校验与事务处理，再调用逻辑流或 Handler 实现。

事件与订阅

业务事件保存已经发生的事实，订阅通过 Outbox 机制至少一次投递；失败交付可诊断和显式重驱，消费逻辑需要处理重复投递。

访问控制

菜单、页面、接口与数据访问分别受权限约束。后端继续校验身份、角色和凭据授权，数据模型执行行级条件与字段范围。

07

部署应用，也要分清环境与资产边界

开发环境保存工作区与平台管理数据，应用运行环境保存自己的定义、配置和业务数据。实例可以重建，需要保留的数据应独立持久化。

环境隔离

开发、测试和生产分别管理入口、凭据、数据源与持久化目录；应用元数据、日志、上传文件和数据库按用途保存。

部署形态

原生、容器与云原生形态承载相同的应用定义和基座。仓库提供镜像与 Compose 安装材料，集群安装清单按目标环境准备。

交付衔接

版本管理保存已验证的模型与代码组合。生产部署、发布和恢复衔接团队已有流程，数据变更另行管理；独立运维平台仍在规划中。
